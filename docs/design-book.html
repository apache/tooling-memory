The box, the record, and the line between them.

amem runs a coding harness in a box with no network, keeps what it learns on a record of versioned Markdown, and meters everything that crosses from one to the other. Its web pages show all three at once. This book fixes how they look and what each colour means, so the next page is a composition rather than an invention.

01Principles

Nine rules. Each one is applied somewhere in this book, and the decisions in chapter 20 say where each came from.

  1. One decision, made once. Which colour a state takes, how an id is set, what a disabled button says: answered here, not per page.
  2. The page and the terminal speak one palette. The six hues are ANSI's six colours. Red in a harness's output and red on a chip are the same red, meaning the same thing.
  3. One meaning per hue. The table in chapter 02 is exhaustive. A state that is not in it has no colour.
  4. A chip marks an exception, not a fact. A label, a trust tier, a count of tokens are true of every entry or every session. They are set as text in their place, not as coloured badges.
  5. Colour is never the only carrier. Every state has a glyph and a word, and the word is always in the accessible name.
  6. Mono means exact characters. Ids, commands, digests, paths, model names. Nothing else is set in it.
  7. What crosses the line is on screen. Destination, ceiling, usage, entries mined, handoffs waiting: the numbers the paper measures sit on the session's frame for as long as it runs.
  8. It needs nothing it does not carry. No CDN, no fonts fetched, no build step. The system font stacks are a design in their own right, not a fallback to apologise for.
  9. Both themes are designed, and a stated preference is honoured without being found. Dark, more contrast and reduced motion follow the system unless the reader says otherwise.

Four of those deserve their reasoning stated.

  • Labels and trust take no hue. Every entry has both, so by the chip rule they are facts. The obvious alternative, public green and restricted red, would spend the hues that mean passed and refused on a property that is neither good nor bad; a restricted entry is not a failure. They are ordered values, so they are drawn as orders: the label mark fills one, two or three bars, and the trust mark fills a disc: empty, half, whole.
  • A running session is live, not ok. Nothing has been checked yet, and a row of green running sessions would read as a row of successes.
  • Below the ceiling has no colour. It is the normal case. A session at its ceiling is a warning because the filter is now hiding entries above it, which changes what the harness can find; a refused call is a failure because something the harness asked for did not happen.
  • Await is violet for the same reason BAT's comments are: it is the hue that says a person needs to look.

A chip marks an exception, not a fact

The rule that keeps the table from growing, taken from BAT unchanged. A chip says this departs from the normal state and may need you. The test is whether the value is true of every row: if it is, it is a column, a line of secondary type, or a mark in a gutter. Every session has a state, so the state is a glyph in the row's gutter; only the exceptional ones (exited 1, refused, to read) also take a chip.

Colour is never the only carrier

Every state has a glyph of its own and a word. The glyph is what meets WCAG 1.4.1 when the word is clipped on a narrow screen; the word is always in the accessible name. Two states sharing a hue never share a glyph: running and claimed are both live, and are a filled dot and a clock.

Contrast, computed

Every pair the tokens are meant to be used in, both themes, with WCAG 2.2 ratios. 4.5 is the floor for text, 3 for a control's boundary, a focus ring or a glyph that carries a state. Decorative rules (--am-rule, --am-rule-soft) separate things that are already separated by space and type, so they are exempt; anything that identifies a control uses --am-edge. The last column is computed by this page, now, from the tokens in force, so it changes when you switch the theme or the contrast above.

03Neutrals and surfaces

Greys biased toward violet, three surface levels, and no shadows. Elevation is a contrast cost a reading tool cannot spare, and borders say the same thing for free.

Plate--am-plate

Three inkson surface

The edge is the one addition to BAT's neutrals. A field whose border is a decorative rule fails WCAG 1.4.11: at 1.36:1, today's input border in the light theme is invisible to a reader with low contrast sensitivity, and the only thing that says you can type here. --am-edge passes 3:1 on all three surfaces in both themes, and more contrast turns every rule into it.

Rules

  • The six normal colours are the six hues, value for value. Bright variants are their lighter neighbours in dark and darker neighbours in light, so bright stays legible on both grounds.
  • The terminal follows the page's theme. A dark terminal in a light page is a hole in it; a light one is designed here rather than left to the harness.
  • minimumContrastRatio: 4.5 on the xterm instance. Harnesses also print 24-bit colours nobody here chose; xterm lifts any of them that would fall under the floor against the ground in force.
  • Selection is a tint of the accent, and text on it keeps 4.5:1. The cursor is the accent, a block, steady: it blinks only if the reader's motion preference allows it.
  • A mem- id is a link, underlined on hover as xterm draws links, and opens in the reading pane.
  • Mono at 14 px, line height 1.2. The terminal is the one place mono is set larger than data, because it is read for minutes at a time.

How a page reads it

The tokens are the only source. The page builds xterm's theme from them, and builds it again when the theme changes.

const css = getComputedStyle(document.documentElement);
const t = (n) => css.getPropertyValue(`--am-term-${n}`).trim();
const names = ['black', 'red', 'green', 'yellow', 'blue', 'magenta', 'cyan', 'white'];
const theme = {
  background: t('bg'), foreground: t('fg'),
  cursor: t('cursor'), cursorAccent: t('cursor-accent'), selectionBackground: t('selection'),
  ...Object.fromEntries(names.map((n) => [n, t(n)])),
  ...Object.fromEntries(names.map((n) => ['bright' + n[0].toUpperCase() + n.slice(1), t('bright-' + n)])),
};
term.options.theme = theme;               // and again on a theme change
term.options.minimumContrastRatio = 4.5;

Mermaid, in the reading pane, takes the same route: its base theme with primaryColor from --am-surface, primaryBorderColor from --am-edge, primaryTextColor and lineColor from --am-ink and --am-muted, and fontFamily from --am-font-sans. No white box behind a diagram in the dark theme, which is what theme: 'neutral' on a forced white ground does today.

05Type

One family and its mono sibling, chosen for the characters this product cannot afford to confuse. Nine roles; a size that fits none of them is a role chosen wrongly.

The faces

Atkinson Hyperlegible Next for everything read, and Atkinson Hyperlegible Mono for everything whose exact characters matter. Both are by the Braille Institute, released in 2025 under the SIL Open Font License 1.1, and both are variable, so two woff2 files cover every weight. They are designed so that a reader with low vision can tell letterforms apart, which is the same problem as telling apart the characters of an id or a digest: l, 1 and I; 0 and O; 5 and S; 8 and B.

Rules

  • Labels are sentence case and not tracked. Weight and position say label; capitals would only say it louder.
  • Mono only for exact characters: ids, commands, model names, digests, paths, profile names. A label beside an id is sans.
  • Entry bodies are prose, in Body at a 68 ch measure. Code blocks inside them are Data and scroll inside their own box; the pane never scrolls sideways.
  • Every size is in rem, so the browser's text size reaches all of it, including the terminal.
  • Numbers that line up are tabular: usage, counts, times in a list.
  • Two weights, 400 and 600, plus 700 for the title and a chip's count.

07Motion

Motion explains where something went. It never decorates a state change, and it never runs unless the reader's preference allows it.

Instant, 0 ms
state, data, selection
Quick, 120 ms

Move, 200 ms

  • Data changes instantly. A session exiting, an entry arriving in the pane, a count on the strip going up: the state is the message, and a transition only delays it.
  • Nothing pulses. A running session's dot is still. In a list of five running sessions, five pulsing dots are noise; the glyph already says live.
  • The busy glyph turns, and only under no-preference. Under reduced motion it stands still beside its word.
  • Named properties only, never transition: all.
  • The durations are tokens that are zero by default and take their values inside @media (prefers-reduced-motion: no-preference). A rule written against them is already right for a reader who asked for stillness.

09The chip

One component carries every exceptional state: glyph, then count, then word. This is its anatomy, its families, and the test a new one must pass.

The full vocabularyno further chip without a change to this book
exited 1 1refused at ceiling to admit 2to read running claimed connecting invalidated superseded demoted erased

Anatomy

  • Glyph, 12 px, the carrier that survives everything else being taken away.
  • Count, tabular and bold, only when there is more than a yes or no.
  • Word, lower case because it reads as part of the row's sentence, and what the accessible name says.
  • Ground: the hue's tint, the hue as text, and an edge of the hue at 40%. In more contrast the tint goes and the edge is the full hue.

Three families

  • Tinted, in one of five state hues: the exceptions that may need you.
  • Outlined ink: exceptions that are not alarms. An entry superseded, a task invalidated. Nothing is wrong; it took a route most do not. The next state of this kind joins them instead of taking a colour.
  • Dashed: provisional. A connection not yet made. The dashed edge says not settled without inventing a seventh hue, the device BAT uses for a change that is yours and not yet committed.

Order, number, and the narrow screen

  • A fixed order: fail, warn, await, live, ink. A column of chips is scannable only if the same chip is always in the same place.
  • At most three on a row; the rest are on the page the row opens.
  • Never in a heading, never in a button, never the only content of a cell whose header says the same thing.
  • Below 480 px chips in a row or on the strip clip their word, never removing it: it stays in the accessible name and the tooltip, and the session page spells it out. In more contrast the words come back at every width.

Adding the next one

A state earns a chip only if it is exceptional (not true of most rows), actionable (a reader would do something differently) and not already implied by what the row says. Earning a chip is not earning a hue: a new exception that is not an alarm joins the outlined ink family. A new hue is a change to the table in chapter 02, and to the terminal's palette with it, which is why there will rarely be one.

12Voice

The repository's own prose style, carried into the interface: plain, concise, sentence case, and no exclamation marks.

  • Name things as the record and the ledger name them. Session, harness, destination, ceiling, label, handling, entry, handoff, task, admit, claim. Not a friendlier synonym, and not an implementation word.
  • A control says what it does, and the result says it happened in the same words. Start session lands on a page whose bar says running. Copy command becomes Copied. Not Success.
  • Sentence case everywhere, including labels and buttons.
  • No exclamation marks, no apologies, no emoji. The repository forbids emoji in commits and code; the interface is the same product.
  • Counts as digits: 2 to read, 12 calls.
  • An error names the operation, the cause, and the next step. It never blames the reader.

16Accessibility

WCAG 2.2 AA as the floor, and the three preferences a reader can state to their system honoured without being found.

  • Contrast: every pair in chapter 02, both themes, passes. The table checks itself in this page.
  • The terminal takes every key, including Tab. So it is never a trap: a skip link before it reaches the reading pane, and F6 moves between bar, terminal and pane. Both are listed under ?.
  • Focus: :focus-visible, a 2 px accent ring, 2 px offset, on every control in both themes; 3 px in more contrast. Never removed.
  • Targets: 24×24 at least, 44 on touch.
  • One h1 per page, the session's title on a session page. Heading levels follow structure, never size.
  • Glyphs are aria-hidden beside a word; a gutter glyph standing alone has role="img" and a name.
  • More contrast (prefers-contrast: more, or data-contrast="more"): muted text becomes body text, every rule becomes an edge, lines and focus rings thicken, chips lose their tints for a solid edge, and clipped chip words come back. Try it with the switch at the top of this page.
  • Reduced motion: the durations are zero unless the reader has not asked for stillness; the cursor does not blink and the busy glyph does not turn.
  • Text size: everything is in rem, the terminal included, and the layout survives 200% zoom by reflowing, never by scrolling sideways.

18Dark mode

Designed, not inverted. Every value has a dark partner chosen for a dark ground, and the meaning of each stays where it was.

  • The mapping does not change. Live is cyan in both, fail is red in both, and the state table reads the same.
  • The hue is the text in both themes. No darkened “text-safe” variant exists to forget: in light every hue is dark enough to read on white, in dark light enough to read on the dark grounds, and the tints are deep rather than pale.
  • The accent fill carries dark text in dark. --am-on-accent flips with the theme, so a rule written as on-accent on accent is right in both. A rule that says white is the one about to be wrong in one of them.
  • The terminal has its own pair, chapter 04. In dark its ground is a step below the surface, so the box reads as set into the page.
  • Three settings, two values. System, light, dark, on data-theme; system is the attribute's absence. The choice persists per browser and is a convenience, never a requirement.
Keeping itHow this system changes without decaying, and what was decided on the way here.

19Governance

A system that cannot be extended gets worked around, and one anyone can extend stops being one. Three gates, matched to what is at stake.

ChangeNeedsBecause
Using the system: a page from existing widgets, a new row in the doctor, new copyNothing. Build it.This is the system working. If composing a page needs a discussion, the book has failed.
A new configuration: a widget variant, a new empty state, a new fieldOne line in the PR description naming the existing thing it extendsCheap to review, and it stops two people inventing the same variant twice.
A new token, hue, chip, glyph meaning or type roleThis book changed in the same PR, the state table and the contrast table with itThese are the things that decay. Each addition is locally reasonable, and that is how one colour comes to mean three things.

Rules that keep it honest

  • tokens.css and this book change together, in one commit. Both files say so at the top. A value in one and not the other is a bug in both.
  • The book changes in the same commit as the page it describes. A book that describes last month's pages is worse than none, because it is trusted.
  • Tokens are named for meaning: --am-fail, not --am-red. When the red changes, every use is still right.
  • Classes are scoped to their component: .am-chip-count, not .n. A short generic name collides silently the moment two components nest.
  • No colour literal outside tokens.css, no transition: all, no px font size.
  • A new hue is a new terminal colour too. There are six ANSI colours and six hues; a seventh hue has no terminal partner, which is the cost to weigh before adding one.
  • A new pair goes in the contrast table, with its ratio in both themes, before the code that uses it.
